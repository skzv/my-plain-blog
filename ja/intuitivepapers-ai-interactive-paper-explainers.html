intuitivepapers.ai で作るインタラクティブな AI 論文解説

著者: Sasha Kuznetsov
2026-06-05
更新日: 2026-11-25

難解な機械学習論文を、検証済みのインタラクティブな解説へと自動的に変換できるでしょうか？

機械学習の論文を読む作業は、もどかしいほど時間がかかります。論文はたいてい新しい提案部分に紙幅を割き、その前提となる5つほどの基礎概念はすでに頭に入っているものとして書かれているため、結局のところ本題を理解する前に古い参考文献の連鎖を辿る羽目になることが半分くらいを占めます。

今どきの手軽な近道は、PDF を LLM に放り込んで解説を頼むことです。私自身よくやりますし、大まかな初見の把握には役立ちますが、意外なほど頻繁に微妙な細部を間違えます。数式の符号が逆になっていたり、導出が厳密なのか近似なのかを取り違えていたり、実際に更新される変数が違っていたりするだけで、アルゴリズムの挙動はまったく別物になってしまいます。しかもその論文をすでによく知っているわけでなければ、一見もっともらしく書かれた解説の中のそうした誤りに気づくのは本当に難しいのです。

私が欲しかったのは、直感と数式を一緒に積み上げていき、しかも実際に触って動かせる図解がついた解説でした。数年前にインタラクティブ勾配降下法デモを作ったとき、それがどれほど大きな違いを生むかを実感しました――スライダーを動かしてアルゴリズムがオーバーシュートしたり収束したりする様子を目の当たりにすることで、静的な数式からは決して伝わらない理解が得られるのです。

DiffusionBlocks から始まった

最初は、Claude と一緒に Sakana AI の DiffusionBlocks 論文の解説ページを1本だけ作ることから始めました。納得のいく形に仕上げるまで、やり取りを重ねておよそ1週間かかりました。その時間の多くは、すべての数式を一次文献（EDM 論文など）や著者の公式 GitHub リポジトリと突き合わせて検証することに費やされました。

その検証の過程で、なんと論文自体に印刷されていた実際の符号ミスまで見つかりました。論文では Δσ = σ_prev - σ_next > 0 と定義しておきながら、式 (4) のオイラー更新を (z - D) と書いており、これだとデノイザーの予測から遠ざかる方向にステップしてしまいます。式 (1) を離散化すると正しくは (D - z) になり、案の定、著者のコード（model.py）を確認すると実装では正しい符号が使われていました。普通の LLM 要約なら論文の誤植をそのまま繰り返していたでしょうし、私自身もおそらく気づかなかったはずです。

そこで私は考えました――この1週間分の作業は、どこまで自動化できるだろうか？論文の実際のソースを取得し、前提となる数学を一次文献や実装コードと照合して検証し、インタラクティブな図解を作り、公開前に自分のドラフトをレビューするパイプラインを構築できないだろうか？

そうして生まれたのが intuitivepapers.ai です。最初は Attention、BERT、GAN、VAE、CLIP、PPO、Mamba、Adam といった定番から最新まで20本の解説からスタートし、パイプラインが定期実行され続けるなかで現在では150本以上の解説へと成長しています。

intuitivepapers.ai のホームページ。

初期の20本の論文ライブラリ。各カードには解説内の図解のライブプレビューが描画されています。

解説ページの構成

各ページは前提知識から始まり、依存関係の順に論文の核心となるアイデアへと積み上げていきます。デスクトップ表示では「コンセプトタワー」と呼んでいるサイドバーがその依存関係の連鎖を可視化してくれるため、各要素がどう積み重なっているかが一目でわかり、短いコードブロックによって数式表記と実際の処理が結びつけられます。

私のお気に入りはインタラクティブな図解です。たとえば PPO は、1ステップで方策（ポリシー）の更新が行き過ぎるのを防ぐためにクリッピング付き目的関数を使います。下の図では、確率比をドラッグし、アドバンテージの符号を反転させることで、目的関数がちょうどどこで平坦になり勾配が出なくなるのかを自分の目で確かめられます。10秒ほどいじるだけで、min の数式をじっと睨んでいるよりずっと早くクリッピングの仕組みが腑に落ちます。

確率比をドラッグしアドバンテージの符号を切り替えて、PPO のクリッピング目的関数を探索する図解。

また、すべての要素はスマホ画面にも収まるよう最適化されています。私自身、スマホで読むことがとても多いからです。

スマホ上の PPO 解説。同じインタラクティブ図解がインラインで動作します。

もう一つの例は CLIP で、画像エンコーダとテキストエンコーダを学習させて一致するペアが揃うようにします。下のインタラクティブなグリッドでは、バッチ内のすべての画像とすべてのキャプションの組み合わせをスコアリングしています――明るく光る対角線上が引き寄せられる正しいペアで、対角線以外は引き離される不一致のペアです。

パイプラインの仕組み

「この論文を解説して」という1回のプロンプトでは、まさに私が避けたかった浅い要約しか出てきません。より信頼性の高い出力を得るために、生成工程を多段階のパイプラインに分割し、ドラフト作成からデプロイまでの間に複数の自動チェックを挟む構成にしました。

まず、モデルに記憶頼りで数式を言い換えさせるのではなく、パイプラインが arXiv の HTML 版（arxiv.org/html/<id>）を取得し、pandoc で MathML を LaTeX に変換することで、論文の数式と数値をそのまま正確に抽出します。

次に、前提概念を一次文献と照らし合わせて定義・符号・記法を検証します。論文の文章だけでは詳細が曖昧な場合は、著者の公式コードを読みに行き、ページ下部の出典パネル（provenance panel）に正確なファイル名と行番号を引用します。これらすべてを検証済みのリファレンスカードにまとめ、執筆担当は元の論文から直接書くのではなく、このリファレンスカードを基にドラフトを作成します。

そこからパイプラインは、チャートライブラリを使わず HTML5 Canvas 上に直接カスタムのインタラクティブ図解を構築し、数式に具体的な計算例と短い擬似コードを添えながら依存関係順に解説を書き上げます。

公開前には、決定論的チェックとモデルによる批評（critic）を組み合わせた検査を通過させます。

  1. コストのかからない決定論的パスが、文章中の典型的な AI っぽい言い回しをチェックし、KaTeX 構文を検証し、狭いモバイル版の数式がスマホ画面からはみ出さずにデスクトップ版と数学的に等価であることを確認します。さらに、すべてのインタラクティブ図解についてデスクトップ・モバイル双方のスライダーやボタン状態を総当たりで走査し、ラベルの重なりや見切れを検出します。
  2. 続いて独立した批評モデル群が、論文との正確性、わかりやすさ、文体、図解、そして実際にレンダリングされたスクリーンショットをレビューします。
  3. 確認された指摘事項は修正パスへ渡され、サイトを再ビルドしたうえで失敗したチェックだけを再実行するサイクルを数ラウンド回します。最後まで解決しない項目が残った場合はフェイルクローズ（安全側に停止）とし、自動公開せずにドラフト PR を開く仕組みになっています。

パイプライン全体は、私のデスクの下にある Mac mini 上で launchd により毎日定期実行されています。毎朝キュー（厳選したバックログと読者からのリクエストを組み合わせたもの）から最も票数の多い論文を取り出し、実行中にモデルのセッション制限に達した場合はクォータのリセットを待って自動再開し、ビルドとレビューゲートをクリーンに通過したら完成ページをデプロイします。

おわりに

1本の論文をきちんと理解したいという動機から始まった試みが、自動検証はどこまで通用するのかという実験へと発展しました。一次文献の照合、著者コードの読解、図解状態の網羅スキャンを組み合わせることで微妙な誤りの多くを防げますが、もちろん出力が完璧になるわけではありません。複雑なインタラクティブ図解は人間の目なしに安定して仕上げるのが依然として最も難しい領域ですし、ときどきぎこちない説明やエッジケースのバグがすり抜けることもあります。

それを補うため、すべてのページの下部にフィードバック欄を設けています。読者からの報告は該当ページの修正だけでなく、今後の解説で同じミスを繰り返さないようパイプラインのルールを厳格化することにも活かしています。

ずっと腰を据えて読もうと思っていた機械学習論文がある方は、ぜひ intuitivepapers.ai を覗いてみてください。読みたい論文をリクエストしたり、キュー内の論文に投票したりできますし、もし解説の中に誤りを見つけたら修正できるようフィードバック欄からぜひ知らせてください。
