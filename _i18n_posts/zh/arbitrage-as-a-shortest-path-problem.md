_有谁不喜欢赚钱呢？_

如果能把「赚钱」这个问题转化为「寻找最短路径」问题，会怎么样？至少有一种经典场景可以做到这一点：利用套利机会。

## 什么是套利？

_套利（Arbitrage）_是指在不同市场之间，或以不同形式买卖资产，从而利用价格差异获利的行为。而从事套利的人被称为_套利者（Arbitrageur）_——听起来确实挺高级的。

我们先来看一个简单的例子。假设保罗（Paul）、彼得（Peter）和鲍勃（Bob）住在一个村子里，他们以物易物，交换胡萝卜、土豆和生菜。鲍勃用土豆换胡萝卜，彼得用生菜换土豆，保罗用生菜换胡萝卜。

进一步假设：鲍勃愿意用 2 个土豆换 1 根胡萝卜，彼得愿意用 1 棵生菜换 2 个土豆，保罗愿意用 2 根胡萝卜换 1 棵生菜。如果我们把每个人都看作对应商品的市场，那么兑换率如下所示：

| 市场                           | 兑换率                                     |
|:------------------------------:|:-----------------------------------------:|
| 鲍勃（土豆换胡萝卜）            | 2 土豆/胡萝卜                              |
| 彼得（生菜换土豆）              | 1 生菜/2 土豆 = 0.5 生菜/土豆              |
| 保罗（胡萝卜换生菜）            | 2 胡萝卜/生菜                              |
{% include caption.html content="村子里各种商品的兑换率。" %}

你察觉到其中的机会了吗？

作为一个有商业头脑的人，你自然会想抓住这个机会。假设你手里有 5 根胡萝卜，先去找鲍勃，按他愿意接受的兑换率把 5 根胡萝卜换成 10 个土豆：

{%include math.html content=
"
\begin{align}
5 \text{ carrots} \times 2 \space \frac{\text{potatoes}}{\text{carrots}} = 10 \text{ potatoes} \tag{1} \label{eq:arb_example}
\end{align}
" 
%}

接着，你拿着土豆去找彼得，因为他愿意用 5 棵生菜换你的 10 个土豆。然后你拿着这 5 棵生菜去找保罗，他会用 10 根胡萝卜换你的生菜。

经过几笔聪明的交易，你的胡萝卜财富翻了一倍。你利用套利机会，把 5 根胡萝卜变成了 10 根。

后来，村民们可能会发展出更成熟的市场，不再只有鲍勃、彼得和保罗这三个交易者。这个小村子可能会出现胡萝卜/生菜市场、生菜/土豆市场和土豆/胡萝卜市场，每笔交易的即时汇率会随着大家的交易意愿不断波动。

但套利的原理始终不变。只要以这些汇率挂单交易的人手里还有胡萝卜、生菜和土豆可供兑换，这个机会就可以一直被利用，直到市场重新达到均衡状态。

## 现代市场中的套利

提到现代市场，你首先想到的恐怕不是胡萝卜、土豆和生菜。如果你关注外汇（Forex），想到的多半是美元、英镑和日元。在这种情况下，我们面对的是美元/英镑市场、英镑/日元市场和日元/美元市场，每个市场中都有大量交易者在同时参与。接下来我们就以这些货币作为交易标的来举例，但请记住，这一原理适用于几乎所有可交易的资产。

假设在某一时刻，汇率如下所示：

| 市场                   | 汇率                |
|:----------------------:|:-------------------:|
| 英镑 (£) / 美元 ($)     | 0.8 英镑/美元       |
| 日元 (¥) / 英镑 (£)     | 100 日元/英镑       |
| 美元 ($) / 日元 (¥)     | 0.013 美元/日元     |
{% include caption.html content="外汇市场汇率示例。" %}

如果你从鲍勃、彼得和保罗交易胡萝卜、生菜和土豆的例子里学到了什么，你现在肯定能一眼看出这里的机会。

拿 1 美元换成英镑，你会得到 £0.8。再把英镑换成日元，你会得到 ¥80。最后把日元拿到日元/美元市场换回美元……现在你手里有了 $1.04！

但你必须动作够快，赶在别的套利者之前出手。这种机会转瞬即逝，一旦流动性被耗尽，汇率就会重新趋于一致。

细心的读者可能会发现，我们在例子里没有考虑交易手续费。在实际操作中，你当然必须把手续费算进去，才能判断是否存在真正能赚钱的套利机会。

## 争分夺秒

希望你现在已经直观地理解了为什么速度至关重要。汇率瞬息万变，而且在某个特定汇率上可供成交的「货量」是有限的。

尽管我们目前讨论的例子还算简单，但现实中的套利机会可能跨越很多笔交易，变得极为复杂。我们的例子只用了 3 笔交易，但如果需要 10 笔呢？在一个包含 20 种货币、两两之间都有交易市场的网络中，你能多快找到套利机会？

用计算机来找显然是标准答案。但我们还需要一个高效的算法，免得被别人抢先一步。

为此，我们可以借助数学和计算机科学中的几个巧妙洞见。

<div class="divider"></div>

## 将市场建模为图

图（Graph）是一种极其重要的数据结构，应用极其广泛。许多社会结构和自然结构都可以用图来建模，而事实证明，金融市场也是其中之一。

在我们的场景里，把每种货币看作一个节点（Node）。从一个节点移动到另一个节点，就对应着将一种货币兑换成另一种货币。

![简化的货币图]({{ "/currency-graph-white.png" | prepend: page.imgpath }}){: width="448" height="283" loading="lazy" decoding="async"}
{% include caption.html content="简化示意图——实际上每个方向都应该有一条独立的有向边。" %}

因此，沿着节点之间的边移动，就应该按对应的汇率来换算货币金额。

也就是说，从美元节点移动到英镑节点，相当于乘以 0.8 英镑/美元。我们可以直接把汇率设为每条边的权重（Weight）。

需要注意的是，两个方向的汇率只是_近似_互为倒数。如果美元换英镑的汇率是 0.8 英镑/美元，那么反过来的汇率大约是 1/(0.8 英镑/美元) = 1.25 美元/英镑。这对我们的建模意味着：必须把每个市场上的买入和卖出分别视作两条独立的有向边，各自带有不同的权重。

双向汇率之所以只是_近似_互为倒数，是因为货币买卖价格之间存在微小差价，即买卖价差（Buy-Sell Spread）。举个例子，如果在某一时刻，你可以按 0.8 英镑/美元的价格买入英镑（当前别人愿意卖给你的价格），但把英镑卖回美元时的汇率却是 0.82 英镑/美元（即 1.22 美元/英镑，也就是当前别人愿意从你手里买入的价格），那么你的图模型就会长这样（为简洁起见省去了其他汇率）：

![带汇率的货币图]({{ "/currency-graph-w-exchange-rates-white.png" | prepend: page.imgpath }}){: width="451" height="378" loading="lazy" decoding="async"}

一系列连续交易可以建模为沿着图中的边行进，而最终的交易结果则是把沿途经过的边权重**_相乘_**计算出来的。

## 识别套利机会

既然我们已经建好了模型，那么在图中到底要找什么样的结构，才对应着一个套利机会呢？

要判断一系列交易是否盈利，我们需要一个统一的衡量标准。换句话说，如果交易从美元开始，那最后也必须回到美元。把最终得到的美元数额和最初投入的美元数额一比，就能知道是赚了还是亏了。

在我们的图里，这意味着交易路径必须回到起点节点。在上面的例子中，我们从美元节点出发，最终又回到美元节点。在图论术语中，这叫做**环（Cycle）**。所以我们要找的是某种环——但什么样的环才有利可图呢？

注意，如果我们把沿途边的汇率相乘，有效汇率的单位会逐次消去并转换：

{%include math.html content=
"
\begin{align}
a \space \frac{\cancel{£}}{$} \times b \space \frac{¥}{\cancel{£}} = ab \space \frac{¥}{$}  \tag{2} \label{eq:units_of_exchange_rate}
\end{align}
" 
%}

而当我们回到起点节点时，这个数值就变成无量纲的了——它从汇率变成了收益率倍数！沿着图中的一个环走一圈，把沿途的汇率全部相乘，得到的正是完成这组交易后的回报率倍数：

{%include math.html content=
"
\begin{align}
a \space \frac{\cancel{£}}{\cancel{$}} \times b \space \frac{\cancel{¥}}{\cancel{£}} \times c \space \frac{\cancel{$}}{\cancel{¥}} = abc \space \text{[dimensionless]}  \tag{3} \label{eq:unitless_exchange}
\end{align}
" 
%}

如果市场是完全有效的，所有汇率都处于均衡状态，那么我们的回报率倍数 $$abc$$ 就会等于 1。如果边权重的乘积大于 1，比如 1.02，那就意味着这笔套利能带来 2% 的收益。

因此，推广到任意 $$n$$ 笔交易，一个套利机会对应的就是如下不等式：

{%include math.html content=
"
\begin{align}
\prod_i^n{e_i} = e_ie_2...e_n > 1  \tag{4} \label{eq:arbitrage_return}
\end{align}
" 
%}

其中 $$e_i$$ 表示 $$n$$ 笔交易中第 $$i$$ 笔交易的汇率。

所以，我们需要一个算法，能在市场构成的有向图中找到一个边权重乘积大于 1 的环。你当然可以尝试从头发明一个新算法——但在计算机科学里，就像在生活中一样，把陌生问题归约（Reduce）到我们已经知道怎么解决的经典问题上，往往事半功倍。

## Bellman-Ford 算法

寻找最短路径是计算机科学中非常基础且常见的问题，适用于各种场景。把图和地图对应起来，最直观的例子就是在地图上找最短路线。不过只要动一点脑筋，许多其他类型的问题也能转化为最短路径问题。接下来我要向你证明，寻找套利机会正是其中之一。

首先，明确一下什么是最短路径问题。给定图中的两个节点 $$s$$ 和 $$t$$，最短路径指的是使边权重之_和_最小的那条路径。也就是说，从 $$s$$ 走到 $$t$$，把一路上经过的边权重累加起来，总和最小——即总代价最小——的路径就是最短路径。

接下来，了解一下最短路径问题的不同类别也很有帮助。在最直观的例子——比如在地图上找最短路线——中，所有边的权重都必须是正数。除非你有时光机，否则沿着一条路往前开是不可能让你的行程时间变短的。对于只包含正权边的图，著名的 Dijkstra 算法可以求出到图中所有节点的最短路径。

然而，图完全可以包含负权边。在这种情况下，走过一条负权边会降低整条路径的总代价。但如果图中存在一个总权重为负的_环_，那你就可以一直沿着这个_环_绕圈——每绕一圈，路径总代价就更低一点——于是最短路径的代价会趋近于 $$-\infty$$。面对这种情况，如果最短路径算法能够检测出负权环（Negative Weight Cycle），那就非常关键了，否则算法就会永远陷在负权环里打转。

Bellman-Ford 算法正是这样的算法。作为 Dijkstra 最短路径算法更通用的版本，它能够处理负权边。为此，它具备检测_负权环_的能力——也就是找出图中边权重_相加_小于 0 的环。

但问题来了：我们需要找的是边权重**_乘积_**大于 1 的环，一个只能找边权重**_总和_**小于 0 的环的算法，怎么帮得上忙呢？

## 对数来救场

下一个关键洞见是：利用对数恒等式，可以把乘积变成求和：

{%include math.html content=
"
\begin{align}
\log{ab} = \log{a} + \log{b}  \tag{5} \label{eq:log_product_identity}
\end{align}
" 
%}

这样一来，我们就能把「寻找_乘积_大于 1 的环」转化为「寻找_总和_大于 0 的环」！具体做法就是对每个汇率取对数，将其作为对应边的权重。

我们对不等式两边同时取对数来验证一下。先对左边取对数，就把求乘积转化成了求和：

{%include math.html content=
"
\begin{align}
\log{\prod_i^n{e_i}} = \log{e_ie_2...e_n} = \log{e_1} + ... + \log{e_n} = \sum_i^n{\log{e_i}} \tag{6} 
\end{align}
" 
%}

对右边取对数，正好把 1 变成了 0：

{%include math.html content=
"
\begin{align}
\sum_i^n{\log{e_i}} > \log{1} \rightarrow \sum_i^n{\log{e_i}} > 0 \tag{7}
\end{align}
" 
%}

离目标只差一步了。最后一步，为了彻底归约到已知算法能直接解决的形式，我们把每条边的权重都乘以 -1。这样就把「寻找正权环」变成了「寻找负权环」：

{%include math.html content=
"
\begin{align}
\sum_i^n{-\log{e_i}} < 0 \tag{8}
\end{align}
" 
%}

而这正是 Bellman-Ford 算法的拿手好戏！按上述方式构建图并运行 Bellman-Ford 算法，就能快速高效地帮我们找出套利机会，因为我们已经成功把套利问题转化成了寻找最短路径的问题——更确切地说，是寻找_无限短的路径_。

![负对数货币图]({{ "/neg-log-currency-graph-white.png" | prepend: page.imgpath }}){: width="448" height="283" loading="lazy" decoding="async"}
{% include caption.html content="我们要寻找的是一个负权环，其中每条边的权重都是对应汇率的负对数。" %}

事后回看，负权环与套利机会之间的对应关系其实顺理成章：负权环每走一圈就会降低一次路径代价，而套利环路每走一圈就会让你赚一次钱。其中的精妙之处，就在于通过给边权重取 $$-\log$$，把「乘积大于 1」的问题优雅地转换成了「总和小于 0」。

## 实战验证

我们来用前面例子中的汇率跑一遍这个算法，看看它是否能准确识别出套利机会。对各汇率取 $$-\log$$（自然对数），得到：

| 市场                   | -log(汇率)          |
|:----------------------:|:-------------------:|
| 英镑 (£) / 美元 ($)     | 0.223               |
| 日元 (¥) / 英镑 (£)     | -4.605              |
| 美元 ($) / 日元 (¥)     | 4.343               |

把这几笔交易的权重加起来，不等式成立——_我们找到了一个负权环_！

{%include math.html content=
"
\begin{align}
\sum_i^n{-\log{e_i}} = 0.223 - 4.605 + 4.343 = -0.039 \label{eq:neg_log_exchange_rate_example} \tag{9}
\end{align}
" 
%}

我们可以逆向执行对数变换，还原出乘积并算出回报率：

{%include math.html content=
"
\begin{align}
\prod_i^n{e_i} &= \exp{\sum_i^n{-\log{e_i}}} \\
\prod_i^n{e_i} &= \exp(0.039) = 1.04 \tag{10}
\end{align}
" 
%}

这正好就是我们之前算出来的 4% 回报率。

## 回到现实世界

既然套利机会对应着图里的负权环，那听起来岂不是可以沿着这个环一直绕圈，无限赚钱？现实当然没那么美好。

任何一个套利机会所对应的流动性——也就是在价格发生明显变动之前可以成交的资金体量——都是非常有限的，而且会被各路算法交易员瞬间抢食殆尽；他们为了比对手快上哪怕几微秒，一直在不断逼近计算技术和物理定律的极限。

话虽如此，把图论和经典的最短路径算法应用到金融领域来解决实际问题——顺便聊聊赚钱——依然是一次非常有趣的思维体操，希望你也像我一样乐在其中。
